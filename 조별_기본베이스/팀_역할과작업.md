# 전원 동시에 개발하는 역할 배치

3인: A 접수 / B 처리 / C 현황판. 4인은 D 업무 기록, 5인은 E 보고서를 추가합니다. 모든 사람이 자기 기능을 개발하고 PR을 올립니다. 미배정 영역은 시작 화면으로 남겨도 됩니다.

| 역할 | 담당 파일 | branch |
|---|---|---|
| A | modules/intake/index.js | codex/intake |
| B | modules/processing/index.js | codex/processing |
| C | modules/dashboard/index.js | codex/dashboard |
| D | modules/history/index.js | codex/history |
| E | modules/report/index.js | codex/report |

각자 TASK.md를 읽고 최신 main에서 branch를 만들어 동시에 시작합니다. 다른 영역이 미완성이어도 시작 데이터와 smoke.html로 자기 기능을 확인합니다.

## 교차 검토

A가 B를, B가 C를, C가 다음 사람을 검토하고 마지막 사람이 A를 검토합니다. 3인 A→B→C→A, 4/5인도 같은 원형입니다. 자기 PR을 자기 공식 승인으로 처리하지 않습니다. 병합 진행자 한 명을 정하되 그 사람도 자기 기능을 개발합니다.

구현·PR·검토는 병렬로 하고 main 병합만 한 번에 하나씩 합니다. 담당 파일이 달라 접수가 먼저 병합돼야 처리/현황을 개발하는 구조가 아닙니다. 마지막에는 main을 갱신하고 등록→처리→현황 및 배정한 기록/보고서 반영을 확인합니다. 공통 파일과 문서는 합의 없이 동시에 바꾸지 않습니다.
