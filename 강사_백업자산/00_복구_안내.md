# 강사 복구 안내 — 같은 확인 기준으로 합류

## 기본 원칙

현재 폴더·branch·입력·오류 문장을 확인한 뒤 해당 단계로 복귀한다. 수강생 변경을 삭제하거나 완료본을 자기 결과로 표시하지 않는다. 온라인 화면 관찰과 실제 PR 생성·병합은 구분한다.

| 막힌 지점 | 확인·복구 | 다음 합류와 확인 |
|---|---|---|
| GitHub 가입·로그인 | 사람이 계정·인증을 직접 처리, 계속 실패하면 실제 사이트 캡처 열기 | README 변경 비교 후 2교시 분할표, GitHub 단계 미완료 기록 |
| 저장소 복사·push | 원격 주소·계정·쓰기 권한 확인, 자기 연습 저장소 사용 | 별도 branch의 첫 PR |
| 시작 버전 혼동 | 공개 예시 start 태그와 main 구분, 원본 보존한 새 연습 폴더 준비 | 전체 4건·버튼 미구현 상태 확인 |
| 기능 구현 지연 | start에서 담당 파일과 공통 연결 읽기, 필요한 최소 수정 | 4→3→4 확인 후 PR 검토 |
| 사이트 장애 | 로컬 도구와 실제 캡처로 목적·변경·검토 판단 이어가기 | 확인기록.md에 실제 온라인 미완료 표시 |
| Worktree·Handoff 미지원 | 현재 앱 버전·기능 확인, 별도 작업 폴더와 기록으로 분리 원리 확인 | 기능 실행 여부 구분, branch·PR 실습 계속 |
| 병합 충돌 | 두 목적과 공통 파일 영향 읽고 최종 내용 합의 | 해결 branch에서 실행 후 PR 재검토 |
| Merged 뒤 옛 결과 | 현재 branch·로컬 변경 확인, main 안전 갱신 | main에서 4→3→4 재실행 |

로컬 시작 원본은 ../예시레포/start/, 완료 검증용은 ../예시레포/complete/이다. 해당 폴더 전체를 새 작업 폴더에 복사하고 index.html을 연다. 시작은 전체 4건·기능 미구현이며 완료본은 4→3→CSV 3건→4를 확인한다. 예제결과/index.html은 기존 참고 파일이므로 오늘의 정확한 기능 검증에 사용하지 않는다. 공개 예시의 PR #5·#6 병합 이력과 complete 태그를 완료 비교에 사용한다.

## 복구 뒤에도 직접 확인

필터 4→3→4와 원본 4건을 다시 확인한다. CSV 확장 시 데이터 행 3개·4개를 확인한다. 실제 PR 주소·검토·병합 여부와 백업 사용 범위를 확인기록.md에 남긴다.
